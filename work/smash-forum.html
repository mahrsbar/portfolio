SMASH: a forum with moderation built in

A five-person team had one semester to build a social platform for posting and voting. We shipped a PHP and MySQL forum whose admin can delete a post, ignore a report or ban the user. My part was the thinking around the code: requirements, use cases, software qualities and the report.

The brief

A customer wanted a social web app: accounts, profiles, posts and votes. That's easy to build in a semester and easy to break the moment someone decides to be unpleasant, so my requirements gave moderation the same weight as posting.

Use cases

  • Creating a post. Up to 250 characters, with a live counter; the post can't be submitted over the limit. Validated on the front end and the back end.
  • Viewing posts. Twenty per page, newest first. Click a name to see that person's posts; reposts show both the reposter and the original author.
  • Reporting a post. Any user can report a post; reports collect in the admin's profile.
  • Moderating. The admin can delete the post, ignore the report or ban the user. A ban also deletes the post and blocks login until the person gets in touch.

Software qualities, then tests to match

I wrote ten qualities before most of the code, each defined for this product. Correctness meant every use case worked end to end; robustness meant validation on every form plus auto-logout; usability meant AJAX refresh, quick responses and familiar actions; portability meant responsive and every browser except Internet Explorer. The rest: efficiency, scalability, input validation, documentation, maintainability and user friendliness.

The test plan mirrored the list: correctness tests per use case, robustness tests with bad input, and performance tests with several users on the same post at once. No data collisions turned up.

What it taught me

  • Write the qualities down first. Ten definitions turned "make it good" into a test plan the whole team could run.
  • The admin side needed as much design as posting. Moderation is what kept the forum usable.
  • Writing it up was design work too. Making five people's work read as one system in a forty-page report was my first taste of what I now do every day.
