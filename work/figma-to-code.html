Figma to Code: handoff bundles for AI agents

Most design-to-code plugins try to write the code. This one stopped doing that. It exports a frame as structured context, a ground-truth image, the real asset bytes, and a prompt that tells the agent exactly where every value lives. The agent writes the code, and it stops guessing.

Where every other plugin breaks

I'd been using AI editors with Figma's MCP server to build components, and the results were good when the agent had real context and bad when it didn't. The failures were consistent: approximated colours, hand-drawn icons that "looked similar", fonts silently swapped, images cropped wrong, and "close enough" after one pass.

None of those are code-generation problems. They are context problems. The agent wasn't being given the exact values, the real assets, or a way to check itself.

Psych note

Change blindness

People miss big differences between two images shown side by side; attention has to be pointed at the spot. So the plugin overlays the render on the design and highlights the pixels that differ.

The pivot: emit a spec, not code

The first plan was a six-stage pipeline ending in a React and Tailwind code emitter. Partway through, I realised the emitter was the weakest link: any code I generated would bake in my layout guesses, and the agent would have to reverse-engineer intent from it. So I cut it and made the plugin produce what the agent actually needed:

spec.jsonClean tree: layout, fills, strokes, effects, text runs, variant state
frame.png2× render. Visual ground truth for verification, not measurement
assets/Real SVG and image bytes, deduplicated, optimised
handoff.mdThe prompt: field paths, failure modes to avoid, an iteration loop

Raw values in design vocabulary, with exact size and position on every node. The agent maps them to whatever the codebase needs.

The asset pipeline is a first-class stage

Assets cause more visual mismatches than anything else, so every node is sorted into an asset category with its own export strategy.

  • Image fills. Read the scale mode (fill, fit, crop, tile) and decode Figma's 2×3 image transform into CSS object-fit and object-position. For rotated or skewed crops, rasterise the node instead of emitting fragile CSS.
  • Vectors. Export as SVG, validate that Figma hasn't embedded a raster fallback, normalise to a viewBox, replace single-colour fills with currentColor for icons, and run a conservative SVGO pass that never strips viewBox, IDs, or transformed groups.
  • Icons vs. illustrations. A heuristic on size, colour count, and layer naming decides whether something is an icon (inline, themeable, aria-hidden) or an illustration (single SVG, with a PNG alternative if it gets large).
  • Fonts. Every font is classified as Google, system, or custom. Custom fonts are flagged with a fallback stack so the agent knows to add an @font-face rather than swap the family.

The prompt is the product

The most valuable file in the bundle is the smallest. The handoff prompt does three things a spec can't:

  1. Names the exact field paths. "Canvas dimensions are in meta.size.width. Per-node size is tree.size.width, not node.width." This one section eliminated a whole class of "the data is null" responses.
  2. Lists the shortcuts that fail. Skimming a large spec to "be efficient". Measuring pixels off the PNG instead of reading the JSON. Substituting an icon library for the provided paths. Rounding a badge that says 3. Calling it done after the first draft. Each is a real failure I watched happen and wrote down.
  3. Defines "done" as an iteration loop. Render, compare against the PNG, fix, repeat. The agent has the ground truth; the prompt insists it use it.

The plugin UI as a quality gate

The UI lets you check the match before you export: side-by-side, an overlay with an opacity slider, and a pixel diff with a match percentage. An asset bar flags any image, vector or font that's off, so you know what went wrong before you look at the diff.

Design decisions I'd defend

  • No network access. The manifest allows no domains, and the bundle is a zip you drop into your own agent. Nothing leaves the machine.
  • Hidden layers stay in as commented stubs. The agent should know something was there.
  • Images are not inlined in the spec. They'd blow past the agent's context. SVG paths are inlined because they're small and the agent needs them verbatim.
  • Deterministic naming from layer names. Figma layer names are the designer's intent signal, so they become the section annotations in the output.

What I learned

Generating code is the easy part and the wrong part. Generating context, with clear instructions for using it, produced better code than any emitter I could have written. Design the input, and the AI's output takes care of itself.
