Figma to Code: pixel-faithful handoff bundles for an AI agent

Most design-to-code plugins try to write the code. This one stopped doing that. It exports a frame as structured context, a ground-truth image, the real asset bytes, and a prompt that tells the agent exactly where every value lives. The agent writes the code, and it stops guessing.

Where every other plugin breaks

I had been using AI editors with Figma's MCP server to implement components, and the results were good when the agent had real context and bad when it didn't. The failure modes were consistent: approximated colours, hand-rolled icons that "looked similar", fonts silently replaced, images cropped wrong, and the agent declaring "close enough" after one pass.

None of those are code-generation problems. They are context problems. The agent wasn't being given the exact values, the real assets, or a way to check itself.

Psych note

Change blindness

Show someone two nearly identical photos with a brief blank flicker between them and they can fail, for a long time, to notice a large object appearing or vanishing. Attention doesn't automatically compare scenes; it has to be pointed at a specific location. Side-by-side comparison, it turns out, is one of the worst ways to spot a difference.

That is exactly the failure mode of "does my render match the design?" A designer eyeballing two screenshots misses a 4px padding drift, and an agent declaring "close enough" is doing the same thing. The plugin's overlay scrub and pixel-diff view exist to defeat change blindness: put the two images in the same place and highlight the pixels that differ, so attention doesn't have to search.

Rensink, R. A., O'Regan, J. K., & Clark, J. J. (1997). To see or not to see: The need for attention to perceive changes in scenes. Psychological Science, 8(5), 368–373. · Simons & Levin (1997).

The pivot: emit a spec, not code

The first architecture plan was a six-stage pipeline ending in a code emitter for React and Tailwind. Partway through building it I realised the emitter was the weakest link. Any code I generated would encode my layout heuristics, and the agent would then have to reverse-engineer intent from my output. So I cut the emitter and made the plugin produce what the agent actually needed:

spec.jsonClean tree: layout, fills, strokes, effects, text runs, variant state
frame.png2× render. Visual ground truth for verification, not measurement
assets/Real SVG and image bytes, deduplicated, optimised
handoff.mdThe prompt: field paths, failure modes to avoid, an iteration loop

The plugin's job became extracting structure and intent into an LLM-shaped format. Field names match design vocabulary, defaults and zero values are skipped, assets are referenced by ID, and every node carries its exact size and position. No Tailwind, no inline CSS, just raw values the agent can map however the target codebase needs.

The asset pipeline is a first-class stage

Assets are the number one source of visual mismatch, so the walker classifies every node into an asset category and each category has its own export strategy.

  • Image fills. Read the scale mode (fill, fit, crop, tile) and decode Figma's 2×3 image transform into CSS object-fit and object-position. When the math gets hairy (rotated or skewed crops), rasterise the node flat instead of emitting fragile CSS. Pixel-perfect means knowing when to rasterise.
  • Vectors. Export as SVG, validate that Figma hasn't embedded a raster fallback, normalise to a viewBox, replace single-colour fills with currentColor for icons, and run a conservative SVGO pass that never strips viewBox, IDs, or transformed groups.
  • Icons vs. illustrations. A heuristic on size, colour count, and layer naming decides whether something is an icon (inline, themeable, aria-hidden) or an illustration (single SVG, with a PNG alternative if it gets large).
  • Fonts. Every font is classified as Google, system, or custom. Custom fonts are flagged with a fallback stack so the agent knows to add an @font-face rather than swap the family.

The prompt is the product

The most valuable file in the bundle is the smallest. The handoff prompt does three things a spec can't:

  1. Names the exact field paths. "Canvas dimensions are in meta.size.width. Per-node size is tree.size.width, not node.width." This one section eliminated a whole class of "the data is null" responses.
  2. Lists the shortcuts that fail. Skimming a large spec to "be efficient". Measuring pixels off the PNG instead of reading the JSON. Substituting an icon library for the provided paths. Rounding a badge that says 3. Calling it done after the first draft. Each is a real failure I watched happen and wrote down.
  3. Defines "done" as an iteration loop. Render, compare against the PNG, fix, repeat. The agent has the ground truth; the prompt insists it use it.

The plugin UI as a quality gate

The Preact UI exists to let you see the match before you export. Side-by-side, overlay with an opacity scrub, and a pixel-diff view with a match percentage and clustered mismatch regions. An asset inspector bar reports images, vectors, and fonts as healthy or flagged, so if something looks wrong you know what went wrong before you look at the diff.

Design decisions I'd defend

  • No network access. The manifest allows no domains. The bundle is a zip the user drops into their own agent. Nothing about a design leaves the machine.
  • Hidden layers stay in as commented stubs. The agent should know something was there.
  • Images are not inlined in the spec. They'd blow past the agent's context. SVG paths are inlined because they're small and the agent needs them verbatim.
  • Deterministic naming from layer names. Figma layer names are the designer's intent signal, so they become the section annotations in the output.

What I learned

Generating code is the easy part and the wrong part. Generating context, and being explicit about how the reader should use it, produced better code than any emitter I could have written. This is the same lesson as Figma Export SB from the other direction: design the input, and the AI's output takes care of itself.
